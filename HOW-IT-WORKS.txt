5. THE AUTOMATIC PATH (GitHub push -> running app)
--------------------------------------------------------------------------------

This is the main DevOps loop. There is NO GitHub webhook.

Why no webhook:
  Jenkins lives on localhost:8080.
  GitHub cannot call your PC.
  Instead, a small container POLLS GitHub every 30 seconds.

Step by step:

  1. A teammate (or you) pushes a commit to GitHub
     on the WATCHED branch (today: develop)
     in backend and/or frontend.

  2. Container github-watch runs:
       git ls-remote  (over SSH, using ~/.ssh/id_ed25519)
     every 30 seconds, for each watched repo/branch.

  3. It compares that remote SHA to a file in:
       /home/mikias/workspace/tools/docker-devops/.watch-state/
         collaboration-backend.sha
         collaboration-frontend.sha

     Same SHA  -> do nothing. Jenkins stays idle. Containers stay up.
     New SHA   -> POST Jenkins job  watch-github

  4. Jenkins job watch-github runs.
     It checks again which repo actually moved, then starts ONLY
     the matching job, with ACTION=update-from-github:

       collaboration-backend
       and/or
       collaboration-frontend

  5. That job:
       - git fetch + fast-forward the folder on disk
         (backend or frontend) onto the watched branch
       - npm install inside a node container
       - docker compose up -d --force-recreate that service
       - smoke check (backend hits /api/v1/spaces)

  6. The new code is now running in Docker.
     Frontend: http://localhost:3000
     Backend:  http://localhost:5000/api/v1

If watch-github is idle, GitHub develop has not moved. That is normal.

Check the watcher:

  docker logs jenkins-github-watch-1 --tail 50


--------------------------------------------------------------------------------
6. WHAT HAPPENS IF YOU PUSH A DIFFERENT BRANCH
--------------------------------------------------------------------------------

Example: you push feature/foo or a sprint branch.

Nothing happens.

The watcher only asks GitHub:
  "What is the SHA of develop?"   (or whatever is in .env.docker)

It does not subscribe to the whole repo.

To follow another branch, do NOT edit .env.docker by hand.
Use Jenkins job:

  http://localhost:8080/job/switch-watch-branch/

  1. Build with Parameters
  2. REPO = collaboration-backend  OR  collaboration-frontend
            OR collaboration-both
  3. REBUILD_NOW = checked  (pull + recreate now)
  4. Build
  5. Jenkins lists live GitHub branches and pauses
  6. Pick BRANCH -> Proceed

That job writes the new branch into .env.docker, checks it out on disk,
resets the watcher SHA, and rebuilds if REBUILD_NOW is on.

github-watch re-reads .env.docker every 30s, so it follows the new branch
after that.

Backend and frontend can watch DIFFERENT branches at the same time.

7. MANUAL CONTROL (without waiting for GitHub)
--------------------------------------------------------------------------------

Jenkins UI: http://localhost:8080
Open a job -> Build with Parameters -> ACTION:

  start              start that container
  stop               stop that container
  restart            stop then start
  build-and-start    recreate from current files on disk
  update-from-github git pull watched branch, then recreate

Jobs:
  collaboration-stack       db + redis (+ ES) + backend + frontend
  collaboration-backend     backend (+ db/redis when starting)
  collaboration-frontend    frontend
  watch-github              auto trigger only when SHA changes
  switch-watch-branch       pick which GitHub branch to follow

From the terminal:

  cd /home/mikias/workspace/tools/docker-devops
  ACTION=update-from-github ./jenkins/trigger-build.sh collaboration-backend
  ACTION=update-from-github ./jenkins/trigger-build.sh collaboration-frontend

11. HOW TO TELL WHAT IS WRONG
--------------------------------------------------------------------------------

  Want to see which branch is watched
    open collaboration/.env.docker
    or run Jenkins job switch-watch-branch (it prints "Currently watching")

  Want to see which branch is on disk
    git -C .../backend branch --show-current
    git -C .../frontend branch --show-current

  Push happened but nothing rebuilt
    1. Was the push on the watched branch?
    2. docker logs jenkins-github-watch-1
    3. Jenkins -> watch-github  (idle = SHA did not change)
    4. SSH key can still read the private GitHub repos?

  Containers down
    ./scripts/start-collaboration.sh
    docker compose -f jenkins/docker-compose.yml up -d
